7.1 Outcome vs Process-Supervised Rewards

For complex multi-step reasoning tasks (e.g. mathematical proofs, algorithm synthesis, symbolic logic), evaluating only the final output via an **Outcome Reward Model (ORM)** creates severe credit assignment problems:

  • A model might execute incorrect intermediate reasoning steps but accidentally output the correct numerical final answer (false positive credit assignment).
  • A model might perform 99 correct reasoning steps but fail on the final formatting token (severe false negative penalty).

7.2 Group Relative Policy Optimization (GRPO)

In standard PPO, training a Critic network matching the scale of the LLM Actor (e.g. 70B+ parameters) requires massive GPU VRAM allocation. **Group Relative Policy Optimization (GRPO)** (Shao et al., DeepSeek 2024 / 2025) eliminates the Critic network entirely!

For each prompt query \( q \), GRPO samples a group of \( G \) candidate outputs \( \{o_1, o_2, \dots, o_G\} \) from the old policy \( \pi_{\text{old}} \). Rewards \( \{r_1, r_2, \dots, r_G\} \) are evaluated for each candidate (via rule-based verification or reward models). The advantage \( A_i \) for completion \( o_i \) is computed by normalizing relative to the group:

\[ A_i = \frac{r_i - \text{mean}(\{r_1, \dots, r_G\})}{\text{std}(\{r_1, \dots, r_G\}) + \epsilon} \]

The complete GRPO optimization objective clips policy ratios while penalizing KL divergence against a reference model \( \pi_{\text{ref}} \):

\[ \mathcal{L}_{\text{GRPO}}(\theta) = \frac{1}{G} \sum_{i=1}^G \min \left( \frac{\pi_\theta(o_i|q)}{\pi_{\text{old}}(o_i|q)} A_i, \text{clip}\left(\frac{\pi_\theta(o_i|q)}{\pi_{\text{old}}(o_i|q)}, 1-\epsilon, 1+\epsilon\right) A_i \right) - \beta \mathbb{D}_{\text{KL}}(\pi_\theta \parallel \pi_{\text{ref}}) \]

PyTorch Production Implementation: GRPO Advantage & Surrogate Loss

import torch
import torch.nn as nn
import torch.nn.functional as F

def compute_grpo_advantages(rewards: torch.Tensor, eps: float = 1e-8) -> torch.Tensor:
    """
    Computes group-relative normalized advantages for G completions per prompt.
    rewards shape: (B, G) where B is batch size of prompts and G is group size.
    """
    mean_r = rewards.mean(dim=-1, keepdim=True)
    std_r = rewards.std(dim=-1, keepdim=True)
    advantages = (rewards - mean_r) / (std_r + eps)
    return advantages  # Shape: (B, G)

def grpo_surrogate_loss(
    log_probs_policy: torch.Tensor,  # (B, G, L)
    log_probs_old: torch.Tensor,     # (B, G, L)
    advantages: torch.Tensor,        # (B, G)
    mask: torch.Tensor,              # (B, G, L) sequence mask
    clip_eps: float = 0.2
) -> torch.Tensor:
    """
    Computes token-level GRPO clipped surrogate objective.
    """
    # Sum log probabilities over token lengths
    seq_logps_policy = (log_probs_policy * mask).sum(dim=-1)
    seq_logps_old = (log_probs_old * mask).sum(dim=-1)

    # Probability ratio
    ratios = torch.exp(seq_logps_policy - seq_logps_old)
    advantages_expanded = advantages

    surr1 = ratios * advantages_expanded
    surr2 = torch.clamp(ratios, 1.0 - clip_eps, 1.0 + clip_eps) * advantages_expanded

    loss = -torch.min(surr1, surr2).mean()
    return loss

7.3 Emergent Reasoning Dynamics: DeepSeek-R1 & Test-Time Compute

Training LLMs with pure RL (DeepSeek-R1-Zero) over mathematical and algorithmic verification rewards leads to dramatic emergent behaviors:

  • **Self-Correction & Reflection**: Without human instruction data, the policy naturally learns to emit "Wait...", "Let me re-check this calculation", and "Aha! That step was wrong."
  • **Reasoning Trace Expansion**: Response length automatically expands during RL training as the model generates longer, deeper Chain-of-Thought (CoT) search trajectories.
  • **Test-Time Compute Scaling**: Performance on benchmark suites (MATH 500, AIME 2024, Codeforces) scales monotonically with the log of test-time rollout tokens allocated during inference.
